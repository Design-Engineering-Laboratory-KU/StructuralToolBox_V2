# Structural Toolbox — インストーラの作成（Windows / Mac）

配布物を作る人向けの手順です。受け取った人のインストール手順は [インストール.md](インストール.md) にあります。

2026-09-29〜10-01 に実際にビルド・インストールまで通した手順です。途中で起きたエラーとその対策は「5. 起きたエラーと対策」にまとめています。

受け取る側は **インターネット不要** でインストールできます（Python 本体と解析ライブラリをすべて同梱）。
Grasshopper プラグイン `StbGrasshopper.gha` も自動でライブラリフォルダへ配置されます。

---

## 配布物の一覧

| OS | ファイル | 作る場所 | 受け取った人の操作 |
| --- | --- | --- | --- |
| Windows | `StructuralToolbox_Setup_X.Y.Z_YYYYMMDD.exe`（約 75 MB） | Windows | **推奨**。ダブルクリック → ウィザード |
| Windows | `StructuralToolbox_Windows_X.Y.Z_YYYYMMDD.zip` | Windows | 予備。解凍 → `Install_once.bat` |
| Mac | `StructuralToolbox_Setup_Mac_X.Y.Z_YYYYMMDD.pkg` | Mac | **推奨**。ダブルクリック → 「自分専用にインストール」 |
| Mac | `StructuralToolbox_Mac_X.Y.Z_YYYYMMDD.dmg` | Mac | 開いて `インストール.command` を右クリック → 開く |
| Mac | `StructuralToolbox_Mac_Setup_X.Y.Z_YYYYMMDD.tar.gz`（約 130 MB） | Windows / Linux / Mac | 展開して `インストール.command` を右クリック → 開く |

`X.Y.Z` はソフトのバージョンです。番号はリポジトリ直下の `VERSION` ファイル 1 か所だけに書きます。リリース前にここを書き換えれば、インストーラーの画面・ファイル名、`stb version`、GUI のヘッダー、報告書、Grasshopper プラグイン（`.gha`）のバージョンがすべてそろいます（`tests/test_version.py` で確認できます）。

中身はどれも同じです（同梱 Python 3.12 + 解析ライブラリの wheels + `.venv` の作成 + `stb gui` + Grasshopper `.gha`）。

| | Windows | Mac |
| --- | --- | --- |
| インストール先 | `%LOCALAPPDATA%\StructuralToolbox` | `~/Library/Application Support/StructuralToolbox` |
| 管理者権限 | 不要 | 不要 |
| 対応 OS | Windows 10 / 11（64 ビット） | macOS 12 以降（scipy の Apple シリコン版 wheel が macOS 12 以上を要求するため） |

## 0. 準備（Windows のビルド機）

| 必要なもの | 用途 |
| --- | --- |
| Windows 11 + PowerShell | ビルド |
| `py -3`（Python 3.10 以上） | ビルドスクリプトの実行 |
| [Inno Setup 6](https://jrsoftware.org/isdl.php) | Setup.exe の作成（無料） |
| .NET SDK | `.gha` のビルド（毎回自動でビルドし直します） |
| インターネット | **ビルド時のみ**。Python と wheels を取得（`installer/dist/_cache/` にキャッシュ） |

ビルド前に:

- **Rhino を終了する**（起動中だと `.gha` のコピーが失敗します）
- リポジトリ直下で PowerShell を開く

## 1. Windows 版（Setup.exe）

### 1-1. ビルド

```powershell
.\installer\build_windows_zip.ps1
.\installer\build_windows_installer.ps1 -SourceDir installer\dist\_build\StructuralToolbox_Windows_X.Y.Z_YYYYMMDD
```

- `build_windows_zip.ps1` は配布用フォルダ `installer\dist\_build\StructuralToolbox_Windows_X.Y.Z_YYYYMMDD\` と ZIP を作ります。フォルダだけでよい場合は `-SkipZip` を付けます。
- `build_windows_installer.ps1` は引数なしなら最新の `StructuralToolbox_Windows_*.zip` を使います。ZIP を明示するときは `-ZipPath installer\dist\StructuralToolbox_Windows_X.Y.Z_YYYYMMDD.zip`。
- `build_windows_installer.ps1` は、ペイロードに `Install_once.bat` / `setup_runtime.py` / `python-embed` / `wheels` / `.gha` / 手順書が揃っているかを確認してからビルドします。

出力:

| ファイル | 説明 |
| --- | --- |
| `installer\dist\StructuralToolbox_Setup_X.Y.Z_YYYYMMDD.exe` | **配るのはこれだけ**（約 75 MB） |
| `installer\dist\StructuralToolbox_Windows_X.Y.Z_YYYYMMDD.zip` | 予備（解凍 → `Install_once.bat`） |

### 1-2. 動作確認（ビルド機で必ず 1 回）

```powershell
$dir = "$env:TEMP\stb_verify"
Start-Process .\installer\dist\StructuralToolbox_Setup_X.Y.Z_YYYYMMDD.exe -ArgumentList "/VERYSILENT","/SUPPRESSMSGBOXES","/DIR=$dir" -Wait
& "$dir\.venv\Scripts\stb.exe" doctor --require-bundled     # bundled: yes ならOK
Test-Path "$env:APPDATA\Grasshopper\Libraries\StbGrasshopper.gha"   # True ならOK
& "$dir\unins000.exe" /VERYSILENT
```

`stb.exe` が無い場合は `$dir\install.log` の最後を確認してください。

> アンインストールすると `%APPDATA%\Grasshopper\Libraries\StbGrasshopper.gha` も消えます。
> 開発機で試したあとは `grasshopper\gha\bin\Release\StbGrasshopper.gha` をコピーし直してください。

### 1-3. インストール後の構成

- インストール先: `%LOCALAPPDATA%\StructuralToolbox`（管理者権限不要）
- スタートメニュー: **Structural Toolbox** / **Structural Toolbox (debug)** / **はじめ方**（`はじめ方_インストーラ版.md`）/ **初回セットアップを再実行** / **Structural Toolbox をアンインストール**
- アンインストール: Windows の「アプリ」またはスタートメニューから。`.gha` も削除されます。
- 入れ替え（上書きインストール）: ファイルをコピーする前に `installer/clean_old_install.ps1` が以前のインストールを削除します。対象は、今回のインストール先、前回のインストール先（「アプリ」の登録）、前回の初回セットアップが `StbGrasshopper.location.txt` に記録した場所です。`.venv`・`python-embed`・`wheels` を含めて消しますが、ユーザーが追加した `.dat` / `.out` / `.gh` / `.ghx` / `.project.json` は残し、新しいインストール先へまとめます。配布物かどうかは、ビルドの最後に `installer/write_manifest.py` が作る `install_manifest.txt` で判定します。`.git` があるフォルダには触れません。ログは `%TEMP%\StructuralToolbox_clean.log` です。Mac も同じ規則で、`installer/mac/clean_old_install.sh` が `インストール.command` と .pkg の `preinstall` から呼ばれます（ログは `/tmp/stb-install.log`）。

### 1-4. トラブル

| 症状 | 対処 |
| --- | --- |
| Inno Setup が見つからない | 公式サイトからインストール後、PowerShell を開き直す |
| インストール中に失敗 | `%LOCALAPPDATA%\StructuralToolbox\install.log` を確認 |
| セットアップのみ再実行 | スタートメニュー「初回セットアップを再実行」または `Install_once.bat` |
| 専用 Python を使っているか確認 | インストール先で `.venv\Scripts\stb.exe doctor`（`bundled: yes` が正常） |

## 2. Mac 版

### 2-1. Windows で tar.gz と .pkg 作成スクリプトを作る

```powershell
.\installer\build_mac.ps1
```

初回は GitHub から macOS 用 Python を、PyPI から wheels を取得します（キャッシュ: `installer/dist/_cache/`）。

出力（どちらも Mac に持っていく）:

| ファイル | 説明 |
| --- | --- |
| `installer\dist\StructuralToolbox_Mac_Setup_X.Y.Z_YYYYMMDD.tar.gz` | 本体（約 130 MB）。これ単体でも配布可能 |
| `installer\dist\StructuralToolbox_Mac_make_pkg_X.Y.Z_YYYYMMDD.sh` | Mac で .dmg / .pkg を作るスクリプト（**リポジトリ不要**） |

ビルドの最後に `OK: bundled libraries (38 wheels)` のように表示されます。
**wheels に `uvloop` が含まれていること**が Mac で動く条件です（「5. 起きたエラーと対策」参照）。

### 2-2. Mac で .dmg と .pkg を作る

上の 2 ファイルを Mac の同じフォルダ（例: `~/Downloads/try`）に置き、ターミナルで:

```bash
cd ~/Downloads/try
bash StructuralToolbox_Mac_make_pkg_X.Y.Z_YYYYMMDD.sh
```

`完成: …dmg` と `完成: …pkg` が出れば成功です。同じフォルダに `.dmg` と `.pkg` ができます。

- .pkg は「このユーザのみ」に入り、インストールの最後に同梱ライブラリのセットアップ（2〜5 分）を実行します。管理者パスワードは不要です。
- インストール時に、その Mac で使わない CPU 向けの Python と wheels は削除されます。

> リポジトリ全体が Mac にある場合は `./installer/build_mac_installer.sh` でも作れます。
> このスクリプトを単体で置くと「build_mac.py がありません」になるので、その場合は `make_pkg` の方を使ってください。

### 2-3. 動作確認（Mac で必ず 1 回）

既存のインストールを消してから .pkg を試します。

```bash
rm -rf "$HOME/Library/Application Support/StructuralToolbox"
rm -f /tmp/stb-install.log
open ~/Downloads/try/StructuralToolbox_Setup_Mac_X.Y.Z_YYYYMMDD.pkg
```

完了後:

```bash
"$HOME/Library/Application Support/StructuralToolbox/.venv/bin/stb" doctor --require-bundled   # bundled: yes
ls "$HOME/Library/Application Support/McNeel/Rhinoceros/8.0/Plug-ins/"Grasshopper*/Libraries/StbGrasshopper.gha
```

GUI は `~/Applications`（ホームの「アプリケーション」）またはデスクトップの **Structural Toolbox** から起動します。
ブラウザが開かなければ `http://127.0.0.1:8765/` を開いてください。

### 2-4. ログの場所（失敗したとき）

| ログ | 絶対パス |
| --- | --- |
| .pkg の postinstall | `/tmp/stb-install.log` |
| 初回セットアップ | `/Users/<ユーザー名>/Library/Application Support/StructuralToolbox/install.log` |
| macOS インストーラ全体 | `/var/log/install.log` |

```bash
cat /tmp/stb-install.log
tail -40 "$HOME/Library/Application Support/StructuralToolbox/install.log"
```

### 2-5. 署名について

Apple Developer ID で署名・公証していないため、初回は「開発元を確認できません」と出ます。
受け取った人には **右クリック（control＋クリック）→ 開く**、または「システム設定 → プライバシーとセキュリティ → このまま開く」で開けると伝えてください（[インストール.md](インストール.md) にも書いてあります）。

## 3. Grasshopper プラグイン

ビルドのたびに `StbGrasshopper.gha` をビルドし直して同梱します（依存 DLL は Rhino 側が提供するため、同梱は `.gha` 1 ファイルのみ）。
初回セットアップ（`setup_runtime.py`）がフォルダを作成してからコピーするので、Grasshopper を一度も起動していなくても入ります。

| OS | 配置先 |
| --- | --- |
| Windows | `%APPDATA%\Grasshopper\Libraries\StbGrasshopper.gha` |
| Mac | `~/Library/Application Support/McNeel/Rhinoceros/8.0/Plug-ins/Grasshopper (b45a29b1-4343-4035-989e-044e8580d9cf)/Libraries/StbGrasshopper.gha` |

- Rhino 起動中はコピーに失敗することがあります。Rhino を終了して `Install_once`（Windows: `.bat` / Mac: `.command`）を再実行してください。
- Mac では検疫属性（quarantine）を自動で外します。
- STB コンポーネントは **Python Exe / Repo Root が空**でも、インストール先の専用 `.venv` を自動で使います。見つからない場合は、PATH 上の Python を使わずエラーにします。

## 4. 専用 Python と Python のバージョン

専用 Python の確認（初回セットアップ内でも自動確認します）:

| OS | コマンド |
| --- | --- |
| Windows | `%LOCALAPPDATA%\StructuralToolbox\.venv\Scripts\stb.exe doctor --require-bundled` |
| Mac | `"$HOME/Library/Application Support/StructuralToolbox/.venv/bin/stb" doctor --require-bundled` |

`bundled: yes` とライブラリ一覧が出れば正常です。

| ファイル | 内容 |
| --- | --- |
| `installer/PYTHON_EMBED_VERSION` | Python の版（Windows と Mac で共通。例: 3.12.10） |
| `installer/PYTHON_MAC_RELEASE` | [python-build-standalone](https://github.com/astral-sh/python-build-standalone/releases) のリリース日（例: 20250409） |

- 版を変えるときは、その Python を含む standalone リリース日に `PYTHON_MAC_RELEASE` を合わせてください。
- Windows 版に同梱した版は、配布物の `python-embed/VERSION.txt` で確認できます。

## 5. 起きたエラーと対策（再発防止メモ）

| 症状 | 原因 | 対策（実装済み） |
| --- | --- | --- |
| Windows: Setup.exe で「pip の更新に失敗しました」。手動実行では成功する | Inno Setup の **RedirectionGuard** が有効だと、`[Run]` から起動した `.venv\Scripts\python.exe` が `0xC00004BC`（STATUS_UNTRUSTED_MOUNT_POINT）で落ちる | `installer/StructuralToolbox.iss` に `RedirectionGuard=no`（`PrivilegesRequired=lowest` なので影響なし） |
| Windows: 別の PC で「pip の更新に失敗しました」、`exit code 3221225477`（`0xC0000005`）で出力なし | その PC に別の Python（Anaconda など）があり、`PYTHONHOME` / `PYTHONPATH` がそちらを指している。`.venv\Scripts\python.exe` はこれらに従うため、別の標準ライブラリを読み込んで落ちる。ユーザーの site-packages（`%APPDATA%\Python\Python312`）が混ざることもある | `setup_runtime.py` は `PYTHON*` / `PIP_*` / `CONDA*` を除いた環境で pip を実行し、`PYTHONNOUSERSITE=1` を設定。起動用 `.bat` / `.command` と Grasshopper コンポーネントも同じ変数をクリアする |
| Windows: 環境変数の対策後も「pip の更新に失敗しました」、`exit code: 3221225477`（`0xC0000005`）。python.org の Python 3.12 が入っている PC で必ず起きる | 埋め込み版 Python は標準ライブラリを `python312.zip` に持ち、`python312._pth` で場所を決める。virtualenv が `.venv\Scripts` にコピーした `python.exe` には `._pth` が無いため標準ライブラリを見つけられず、**レジストリ**に登録された PC 側の Python 3.12 の `Lib` / `DLLs` を読み込み、`ctypes` を import した時点で落ちる（環境変数をクリアしても防げない） | `setup_runtime.py` が `.venv\Scripts\python312._pth` を書き、同梱の `python312.zip` だけを参照させる。`._pth` があると `PYTHONPATH` も無視されて pip のビルド分離が使えないため、同梱の `setuptools` / `wheel` を `.venv` に入れてから `--no-build-isolation` でインストールする |
| Windows / Mac: 古い `.gha` が同梱される | 既存のビルド成果物があると再ビルドしなかった | ビルドスクリプトが毎回 `dotnet build` する |
| Windows: Grasshopper 未起動の PC に `.gha` が入らない | Libraries フォルダが無いとスキップしていた | フォルダを作成してからコピー |
| 開発機: `installer\dist\_build` の古いビルドフォルダが削除・移動できない（「アクセスが拒否されました」） | 配布物に `grasshopper/gha` のソース（`.csproj`、`bin`、`obj`）までコピーしていたため、Cursor / VS Code の C# 言語サーバーがそのプロジェクトを読み込んでロックしていた | 配布物には `grasshopper/gha` のソースを入れず、`README.md` とビルド済みの `grasshopper/StbGrasshopper.gha` だけを入れる。古いビルドフォルダが残っている場合は、Cursor を再起動してから削除する |
| Mac: `.gha` が Rhino に読まれない | 配置先が `~/Library/Application Support/Grasshopper/Libraries`（誤り） | Rhino 8 for Mac の正しいパス（「3. Grasshopper プラグイン」の表）へ配置。アンインストールも対応 |
| Mac: `bash build_mac_installer.sh` で「build_mac.py がありません」 | そのスクリプトはリポジトリ全体が必要 | tar.gz と一緒に `make_pkg_YYYYMMDD.sh` を出力（postinstall 等を内蔵） |
| Mac: .pkg のインストールが失敗、`/tmp/stb-install.log` が空 | 「自分専用」の .pkg では postinstall がユーザー権限で動くのに、`sudo -u` を使っていた（パスワードを求めて失敗） | `installer/mac/postinstall` を root / ユーザー両対応にし、出力を全部ログへ |
| Mac: 「ライブラリのインストールに失敗しました。wheels フォルダが壊れている可能性があります」 | Windows で macOS 用 wheels を集めると、環境判定で Mac 専用の **`uvloop`**（`uvicorn[standard]` の依存）がスキップされる | `installer/fetch_wheels.py` で macOS 向けに `uvloop` を明示追加。失敗時は pip の実際のエラーも画面に表示 |

### wheels を入れ替えたとき

`installer/dist/_cache/wheels/macos`（または `windows`）を削除してからビルドすると、確実に取り直します。

```powershell
Remove-Item installer\dist\_cache\wheels\macos -Recurse -Force
.\installer\build_mac.ps1
```
